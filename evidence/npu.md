# XDNA on Fremont

**CONFIRMED** No PCI function matches an installed amdxdna alias. modinfo -F alias amdxdna reports AMD IDs 1502, 17F0, 17F2, 17F3, 1B0B and 1B0C. All PCI functions including unbound ones were enumerated. The 1022:14ec and 1002:145a instrumentation functions do not match. /sys/class/accel is empty. The running kernel has CONFIG_DRM_ACCEL_AMDXDNA=m, and /usr/lib/firmware/amdnpu/1502_00 contains npu.sbin.zst and versioned npu.sbin.1.5.2.380.zst. Current-boot kernel messages contain no XDNA, amdnpu or standalone NPU/IPU matches. No evidence of a failed XDNA probe, firmware upload or bound accelerator. [Linux PCI ID table and revision matching](https://github.com/torvalds/linux/blob/master/drivers/accel/amdxdna/amdxdna_pci_drv.c)

The local PCI evidence disproves the hypothesis of a supported, enumerated XDNA function merely missing its driver. This driver selects NPU1 for 1022:1502 revision 00. Its SVA path also requires appropriate IOMMU support. This boot requests amd_iommu=off. That can matter to an enumerated device's usability, but does not explain disappearance of a PCI function.

**STRONG EVIDENCE against a usable NPU by design.** The exact AMD signature identifies Hawkpoint2, and AMD excludes the 8540U commercial comparator from Ryzen AI support. Some other Ryzen 8040 models expose XDNA. AMD's feature table answers a product support question. Physical absence on this individual piece of silicon remains UNKNOWN. No positive local evidence supports a dormant XDNA array, firmware gating, or fuse disablement. See acpi.md for the firmware namespace evidence. [AMD 8040 reference guide](https://www.amd.com/content/dam/amd/en/documents/partner-hub/ryzen/amd-ryzen-8040-series-quick-reference-guide.pdf)

An existing AMD/Valve ordering-code-to-mask mapping or annotated production die floorplan could resolve physical presence. If an XDNA block were exposed and initialized, the relevant use would be supported inference workloads. No such endpoint exists here.
