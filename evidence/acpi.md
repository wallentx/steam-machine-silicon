# Firmware describes an IPU endpoint

**CONFIRMED** on Fremont F7F0108. The cached ACPI namespace exports `\_SB_.PCI0.GP18.IPU_`, address 1. Its parent exports address 0x00080002 and links to 0000:00:08.2, whose secondary bus is 08. The corresponding PCI endpoint would be 08:00.1. Only 08:00.0 (1022:14ec dummy) enumerates on that bus. IPU_ has no physical_node symlink. Firmware supplies a specific location for an IPU. Device presence, power state, and the reason for non-enumeration are UNKNOWN.

**CONFIRMED** on the CPU graphics branch. GP17.VGA_ links directly to the dummy graphics function 07:00.0. GP17.ACP_ names function 5, where PCI has no device. Both have PWRS namespace objects. ACP_ has HDA0, PDMC, I2SC, BTSC, SDWC, SDWS and USBS child names. The discrete graphics path runs through GPP0.SWUS.SWDS.VGA_. The live kernel reports 28 AML tables and lists OEMACP and CPMACPV5 SSDTs. Namespace names describe the platform firmware's device model. They give no measurement of fuse state or audio DSP activity.

Run scripts/inspect-acpi.sh to reproduce the path, _ADR, and kernel physical-node associations using sysfs metadata. See firmware.md for the board capsule AML. As initially tested the live DSDT was root-readable and sudo -n cat required authentication. The local iasl disassembler was unavailable. A complete search for supplementary methods, _CRS, interrupt routing and _STA overrides in all live SSDTs therefore remained open at this stage. The script's --tables mode copies only DSDT/SSDT data and disassembles offline when iasl is on PATH.

## Completed live table inspection

The owner copied the DSDT and 27 SSDTs. All 28 lengths and ACPI checksums validated. A private extracted ACPICA 20251212 iasl binary from the Arch extra package was signature-checked against the system Arch keyring and run on these files. The combined namespace pass reported duplicate objects. Individual SSDT disassembly produced all remaining listings. External-method argument inference in isolated listings can be incomplete. To reproduce with iasl in PATH, in raw/aml run iasl -d on each .aml file separately. No AML method evaluation is needed.

The live DSDT.dsl line 1207 gives the same complete IPU DeviceOp as the capsule, containing only _ADR=1. SSDT17.dsl line 430 also names the IPU path as a string within a package alongside other platform devices. SSDT4.dsl line 427 supplies ordinary PCI interrupt routing for the parent GP18. No IPU-specific MMIO range, interrupt, _STA gate, power sequence or initialization method was found by name across these listings. Indirect references and pre-OS firmware policy remain possible. SSDT27.dsl line 418 independently defines ACP _PS0 and _PS3 methods. Their presence establishes firmware power-management support for the named audio function. The corresponding PCI address is empty this boot.
